# Problem Analysis
The error "Failed to create container. Check image name exists and Docker has permissions." occurs when creating containers via the GUI. This error is generated in the backend API endpoint when the container creation returns a falsy value (None or False).

## Root Cause
In `backend/app/services/container_service.py`, the `create_container` function returns `None` on various failure conditions:
1. When Docker client is not initialized
2. When pulling image fails (currently returns error dict, but function continues)
3. When APIError or ImageNotFound occurs during container creation
4. When unexpected exceptions occur

The API endpoint in `backend/app/api/endpoints.py` treats any falsy result as a generic failure and shows the static error message, hiding the actual underlying error.

## Solution
Modify the `create_container` function to return detailed error information instead of `None`, allowing the API endpoint to relay specific error messages to the user.

### Changes Required
1. **backend/app/services/container_service.py**:
   - Replace `return None` when Docker client is not initialized with `return {"error": "Docker client not initialized"}`
   - Replace `return None` on APIError/ImageNotFound with `return {"error": f"Failed to create container: {str(e)}"}`
   - Replace `return None` on generic exception with `return {"error": f"Unexpected error creating container: {type(e).__name__}: {str(e)}"}`
   - Keep existing pull failure error dict format (includes suggestion)

2. **Verification**:
   - Ensure API endpoint correctly handles error dicts (already implemented)
   - Test container creation with various failure scenarios
   - Confirm success case still returns container info dict
