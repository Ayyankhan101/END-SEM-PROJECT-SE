# Plan: Fix Login Page Password Change Issue

## Problem
The user reports that `/api/auth/token` returns 403 Forbidden and there's no way to change passwords through the GUI login page. The system correctly requires password changes (default admin with `must_change_password=1`), but users cannot complete this flow because:

1. Login endpoint returns 403 when `must_change_password=1` instead of a structured response indicating password change required
2. No UI flow exists for forced password change
3. Password change endpoints exist but aren't integrated with the login flow

## Root Cause Analysis

### Backend (Already Fixed)
- `endpoints.py` login function correctly checks `user.must_change_password` and returns 403 with header `X-Force-Password-Change: true`
- Password complexity validation is enforced (12+ chars, upper/lower/digit/special)
- Force-change endpoint exists at `/auth/force-change-password`

### Frontend (Missing)
- No UI component to handle password change requirement
- No redirect or modal when 403 with `X-Force-Password-Change` header is received
- Password change form doesn't exist in login flow

## Solution Plan

### Phase 1: Backend API Enhancement (Required)
**Current behavior:** Returns 403 Forbidden which browsers/treat as generic error
**Desired behavior:** Structured response allowing frontend to handle gracefully

1. Modify login endpoint to return 403 with JSON body indicating password change required (instead of just headers)
2. Keep backward compatibility with `X-Force-Password-Change` header
3. Ensure CORS allows frontend to read the response headers/body

### Phase 2: Frontend UI Implementation (Required)
**Location:** `frontend/src/` (likely App.vue or login component)

1. Create password change modal/component
2. Detect 403 with password change header/body on login
3. Show password change form instead of error
4. Call `/auth/force-change-password` after successful change
5. Re-authenticate with new password
6. Store JWT and redirect to main app

### Phase 3: User Experience Flow
1. User visits app → sees login form
2. Enters admin/admin123 (or any account with must_change_password=1)
3. Receives 403 with password change requirement
4. Modal appears: "Password change required" with fields:
   - New Password (with strength indicator)
   - Confirm New Password
5. On submit → calls force-change-password endpoint
6. On success → automatically logs in with new password
7. Stores token → redirects to dashboard

### Phase 4: Additional Improvements
1. Add "Forgot Password" flow for users who don't know current password
2. Add password strength meter
3. Add password change option in user settings (for users who know current password)
4. Add admin panel to force-reset user passwords

## Technical Details

### Backend Changes Needed
File: `backend/app/api/endpoints.py`
- Modify login response at line ~102 to include structured error body
- Current: `raise HTTPException(status_code=403, detail="Password must be changed", headers={"X-Force-Password-Change": "true"})`
- Keep this but ensure frontend can handle it

### Frontend Changes Needed
Files to create/modify:
- `frontend/src/components/PasswordChangeModal.vue` (new)
- `frontend/src/views/Login.vue` or `frontend/src/App.vue` (modify login handling)
- `frontend/src/services/api.ts` (add password change API call)

### API Flow
```
1. POST /api/auth/token {username, password}
   ← 403 {detail: "Password must be changed"} + header X-Force-Password-Change: true

2. POST /api/auth/force-change-password {new_password} (with Bearer token from step 1... wait)
   Issue: No valid token yet!

Solution: Include minimal user info in 403 response or use separate endpoint:
2a. POST /api/auth/force-change-password {username, old_password, new_password}
   ← 200 {status: "success"}

2b. Then POST /api/auth/token again with new credentials
```

Actually, looking at the code more carefully:
- `force-change-password` endpoint uses `Depends(get_current_user)`
- This requires a valid token
- But user can't get a token because password must change
- **This is a circular dependency!**

## Critical Issue Identified

The `force-change-password` endpoint requires authentication (`current_user = Depends(get_current_user)`), but users who need to change password CANNOT authenticate (403). 

### Solutions:

**Option A:** Create separate endpoint that doesn't require auth
- `POST /api/auth/change-password-with-old` {username, old_password, new_password}
- Validates old password, changes to new, doesn't require token

**Option B:** Modify force-change to accept username/password instead of requiring token
- `POST /api/auth/force-change-password` {username, old_password, new_password}
- Verify old password manually, then update

**Option C:** Login returns special token even with must_change_password
- Token includes `must_change_password` claim
- Frontend uses this token to call change endpoint
- After change, token is revoked and new one issued

**Option D (Best):** Combine login and password change
- Login with must_change_password=1 returns 403 with user info
- Separate endpoint: `POST /api/auth/change-password-first-login` {username, old_password, new_password}
- No auth required, just validates credentials

## Implementation Plan (Revised)

## Additional Notes

The 403 status is correct per HTTP spec (authentication succeeded but access denied due to policy), but the UI needs to handle this gracefully. Many systems use 403 for "password expired/change required" scenarios.

Alternative approach: Return 428 Precondition Required (RFC 6585) which specifically indicates the origin server requires the request to be conditional. However, 403 is widely used and understood.

The key is providing structured error information the frontend can use to trigger the password change flow.
